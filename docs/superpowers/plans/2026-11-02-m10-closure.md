# M10 automated evaluation and loaded-use qualification

Historical implementation plan from 2 November 2026. Its execution sequence is
retained for context; current completion criteria and results are recorded in
the [specification](../../SPECIFICATION.md) and
[roadmap](../../ROADMAP.md#automated-host-experiment-and-retained-use-qualification).
The bounded experiment's completed denominator includes failed and unrun rows;
this plan must not be read as a claim that all 300 rows executed successfully.

Requirements: RM16, RM35, RM37, RM39–RM44; AC28, AC30–AC36.
Normative contract: `docs/SPECIFICATION.md` sections 7.6.1 and 12.6.7.

## Delivery sequence

1. Keep the CI budget change in a separate PR without an associated issue.
   Test PR, master push, tag, and manual events. macOS runs only for master
   pushes. Preserve Linux/Windows checks and cancellation of superseded PRs.
2. Revise the specification before implementing the automated experiment.
   Preserve production manual selection and action authority. Model proposals
   in this experiment select offered metadata only, never authorize actions.
3. Validate frozen driver, judge, reviewer, budget and source bindings; test
   malformed, stale and invented selections before implementing the runner.
   Journal every dispatched row durably and preserve unknown consumption.
4. Freeze the actual host executor, protocol, release, catalog, prompts and
   equal generation limits in a new preregistration commit. Preserve the
   historical #260 inputs unchanged. Execute the complete 100-task cohort,
   blind-judge all arms, and retain two separate machine review records.
   A helper test or incomplete report cannot close #277.
5. For #280, first test the actual pinned transport's stop boundary with a
   receiving HTTP recorder and a paired positive control. Then acquire a
   retained borrow from real admitted native ingress and demonstrate its
   lifetime, current-person binding and supported fresh library access at the
   provider boundary. Doubles cannot establish those host facts.
6. Connect a qualified boundary only after real-host experiments establish
   those properties. Capture positive, stale, deletion, reset and revocation,
   including interventions while dispatch waits. Preserve each refusal and
   receiving-request count. Commit either passing qualification or evidence
   establishing the host limitation; absence of access is not such evidence.
7. Independently review the complete diff and evidence, including a separate
   OpenCode 2 review. Fix important findings in these PRs, without creating
   follow-up issues. Run Python tests, lint/format, plugin tests/typecheck,
   and packaging checks appropriate to changed files before finalizing.

## Release claims

Do not enable loaded use or close either issue based on scaffolding. The
100-task execution and real-host captures remain release prerequisites.
Report automated evidence as automated; omit authorship attribution from
commit and PR prose. The CI PR can ship independently of qualification.
